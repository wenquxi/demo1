## 网络坑：GitHub 拉不动（值得记住）

- 沙箱代理 `127.0.0.1:62147` 对 github.com / codeload 反复 502、且大文件传输被截断，
  `git fetch` 出现 `unpack-objects failed` / `early EOF`。
- **本机 `127.0.0.1:7890`（用户自己的代理）可用**：`env https_proxy=http://127.0.0.1:7890
  git fetch ...`。`api.github.com` 在默认沙箱代理下也能通，github.com 不行。
- corner-shop 的 origin 是 SSH（`git@github.com:44856/...`），本机 `~/.ssh/id_rsa`
  **没有**该仓库权限（Permission denied publickey），只能走 https URL 拉。
- 截断拉取会在 `.git` 里留下部分对象 + 伪 `remote."<url>".promisor=true` 配置；
  清理方法：删掉该 remote section、`core.repositoryformatversion` 复位 0、
  再删 `.git/shallow`（父提交本地都有，删掉即可恢复连通性）就能正常 ff 合并。

## （续）corner-shop 地形重做：去草原 → 土路平地 → 大理石

详细记录见 `F:/demo1/corner-shop/.workbuddy/memory/2026-10-20.md`。这里只留三条可复用的：

- **albedo 别给太高**。Godot 里日光 1.2 + 天空 ambient 0.85 + filmic + 饱和 1.22 的组合下，
  albedo 0.9 的石头必然纯白一片（我没意识到这点，第一版大理石直接炸了）。
  土 0.41、石 0.37、大理石 0.50 才是这个光照下的合理档位。
- **亮度差在 sRGB 输出下会被压扁**：线性差 57% ≈ 屏幕差 10%，想让人「看出渐变」要么把
  差拉到 ~2 倍，要么改用色相差（暖褐 vs 冷白）。这是做程序化地表时最反直觉的一条。
- **程序化砖缝 + `fwidth` 抗锯齿有个陷阱**：远处缝宽会铺满整块砖，此时固定的「缝压暗」
  等于给整片地盖灰罩，越远越黑。压暗量要跟着 fwidth 自己收回 1.0。
